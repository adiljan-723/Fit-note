贵公司目前是宠物家庭寄养平台，从岗位描述看，并不是单纯招一个只写页面的人，而是希望找到能在早期团队里把想法快速做成产品的人。

  • 用 AI 写代码，把产品想法快速变成真实可用的东西；
  • 做落地页、微信 H5、小程序迭代；
  • 做宠物档案、订单管理等轻量系统；
  • 对接微信生态工具，例如企业微信、电子签等；

  • 适应早期创业团队的不确定性。
我做的 Fit Note 虽然是健身方向，但底层结构和宠物寄养平台非常接近：资料管理 → 计划/任务 → 每日记录 → 状态汇总 → 知识库 → 后续云端同步。

二、Fit Note 项目简介

Fit Note 是我用 AI 编程工具辅助完成的微信小程序，目标用户是健身房新手和入门用户。它解决的问题是：用户不知道今天练什么、不知道动作怎么做、训练记录麻烦、练完后看不到完成情况。

当前 v0.7.3 已实现

  • 首页仪表盘：展示今日训练、完成度、本周数据、饮食状态；
  • 用户资料：记录性别、年龄、身高、体重、训练目标、训练时长；
  • 训练计划：支持增肌/减脂计划生成和自有计划；
  • 今日训练：按当天计划展示动作，并可一键进入记录；
  • 训练记录：逐组记录重量和次数，支持复制上一组、复制上次训练、休息计时器；
  • 饮食记录：记录热量、蛋白质、饮水目标；
  • 动作库：按部位分类，支持搜索和动作详情；
  • 动作详情：动作步骤、训练要点、常见错误、图解占位、视频字段预留；
  • 本地缓存：使用 wx.getStorageSync / wx.setStorageSync 保存数据。
这个项目的重点不是“健身”本身，而是把一个线下行为拆成线上可执行、可记录、可复盘的流程。

三、Fit Note 功能如何迁移到宠物寄养平台

后续云同步多设备订单/档案/记录同步支撑正式运营

我可以这样理解贵公司的产品：宠物寄养不是简单展示服务，而是一个“宠物档案 + 订单 + 照护流程 + 反馈报告”的轻量管理系统。

四、如果为贵公司做小程序，我的第一版思路

我不会一开始就做很复杂的平台，而是先做一个能跑通服务闭环的小程序 MVP。

1. 首页/服务落地页平台定位、服务流程、安全保障、常见问题、立即咨询/预约按钮。
2. 宠物档案宠物姓名、品种、年龄、性别、体重、疫苗、性格、饮食习惯、禁忌、用药、照片。
3. 订单管理寄养开始/结束时间、服务类型、宠物数量、订单状态、照护人、价格、备注。
4. 每日照护任务早餐、晚餐、饮水检查、遛狗、排便记录、用药、拍照反馈、异常观察。
5. 照护记录喂食、饮水、排便、活动、精神状态、照片/视频、异常情况、备注。
6. 自动寄养日报根据照护记录自动生成给主人看的反馈，减少人工编辑消息。
订单状态建议：待确认 → 已确认 → 寄养中 → 已完成 → 已取消

六、我对微信生态工具对接的理解

  • 企业微信：客户咨询、服务群、客户标签、复购维护。

宠物平台云数据库集合

十、面试可能被问到的问题

Q1：这个健身小程序和我们宠物平台有什么关系？
业务不同，但系统结构很像。Fit Note 是用户资料、计划、记录、总结、知识库；宠物寄养平台也需要宠物档案、订单、照护任务、照护记录、寄养日报和护理知识库。我做这个项目的核心收获是把线下流程拆成线上可记录、可追踪、可自动化的系统。
Q2：如果入职后先让你做一个功能，你会做什么？
我会建议先做宠物档案 + 每日照护记录。因为这是寄养服务的基础，也最能提升主人信任感。第一版不需要很复杂，先把宠物信息、喂食、饮水、排便、活动、照片和异常情况记录下来，再自动生成给主人看的日报。
Q3：你的小程序现在有没有后端？
当前是本地缓存版，适合早期验证。后续正式上线我规划使用微信云开发，包括 openid、云数据库、云函数、多设备同步和数据导出。虽然我还需要在真实业务里继续学习后端落地，但我已经理解从本地缓存升级到云端的基本路径。
Q4：你怎么使用 AI 编程工具？
我会先明确需求和页面逻辑，再让 AI 辅助生成代码、修改样式、排查错误和整理文档。比如这个项目里，我不是只让 AI 随机写代码，而是不断提出具体需求：计划页怎么改、训练记录怎么逐组记录、动作库怎么设计、页面空白怎么排查。
Q5：你能适应早期创业团队吗？
我对早期团队是有兴趣的，因为早期更需要快速试错和主动推进。我知道需求可能不完整、变化也会比较快，所以我愿意多沟通、多学习，从小功能开始做，先把能用的版本做出来，再根据反馈迭代。
